# K-0033 — Ikili temsil: insan-metni (md) ↔ makine-cekirdegi (json); derleyici manager LLM, dogrulayici round-trip checker (ONAYLANDI 2026-10-13 — kullanici: "k0033 onayliyorum")

## Baglam
Ordu yonetimi onyuzde insan-okur metin olacak; kullanici gorevleri duz metin duzenleyip atayacak. Arkada manager LLM bunu makine-okur formata cevirip kodun kalbine yerlestirecek (test edilebilir, denetlenebilir). DAG/task-graph gibi agir yonetim yapilari bilincli olarak reddedildi — basitlik sart. Soru: makine formati ne olsun?

## Karar
1. **Iki katman, tek dogru:** insan yuzeyi `plan.md` (kisitli Markdown, satir-basi gorev formati) · makine cekirdegi `emirler.json` (tek otorite, append-kilitli — K-0020 D2-06). Cekirdek JSON; yuzey Markdown. Dashboard JSON'dan okur, duzenleme md'den yapilir.
2. **Derleyici = manager LLM:** md → json derlemesini manager yapar (SPAWN/EMIR mesaji gibi yapilandirilmis cikti uretir, dosyaya dogrudan yazamaz — plugin isler).
3. **Dogrulayici = round-trip checker (plugin, deterministik):** derlenen JSON'dan kanonik md geri uretilir; insanin md'siyle anlam karsilastirmasi yapilir. Ek sartlar: JSON schema gecerli · id'ler tek · bagimlilik grafigi DONGUSUZ (topo-siralama; dongu = red) · her gorevde olculebilir kabul kriteri · izinler.json disi dizin yok. Hepsi gecmeden append yapilmaz — fail-closed.
4. **Suruklenme (drift) kilidi:** md ve json ayriliginda checker "ESLESMEDI" der; yuzey kirmizi gosterir, tek tikla yeniden derleme. Hangisi dogru? — json otoritedir ama insanin md'si son duzenlemeyi tasir; cakismada insan surumu kazanir, json yeniden derlenir.
5. **Kod gibi yerlesik:** emirler.json git'te versiyonlanir; her derleme commit + checker ciktisi (kac satir derlendi, kac red) damgalanir. Degisiklik denetimi = git diff.

## Reddedilen alternatifler
- Saf JSON'u insanin duzenlemesi: parantez/virgul hatalari, Turkce metin icinde tirnak kacislari — insan-duzenlenebilir degil.
- YAML: girinti hatalari ve tip belirsizligi (evet/hayir → bool) bu kullaniciya gereksiz risk.
- Serbest Markdown + regex parse: kirilgan; kisitli satir formati + LLM derleyici hem esnek hem dogrulanabilir.
- DAG/task-graph kutuphanesi (Temporal, Airflow tarzi): kullanicinin acik reddi — karmasik; satir-liste yeterli.
- Tek katman (sadece md veya sadece json): ya makine okuyamaz ya insan duzenleyemez.

## Sonuc / riskler
- Round-trip checker sistemin guvenlik supabidir: manager'in anlam kaymasi (halusinasyon) json'a ancak checker'i gecemeden girer — checker deterministik, LLM degil.
- Risk: "anlam karsilastirmasi" kismi LLM'siz zor — v1'de kural-bazli (gorev id/baslik/sahip/kabul alanlari birebir eslesme), semantik esleme gerekiyorsa vekil pitbull ikinci gecis yapar. Basit basla, olc, gerekirse derinlestir.
