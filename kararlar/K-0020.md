# K-0020 — Görev Emri Orkestrasyonu (Pano Sekme 2) (TASLAK 2026-10-12 — kullanıcı onayı bekleniyor)

## Bağlam
Ajanlara görev elle veriliyor; sıralama, durum görünürlüğü ve şema zorlaması yok. K-0016 çok-reviewer kuralları kanıtlandı; K-0018 mod sistemi kilitli. Eksik halka: görevlerin yazılabildiği, sıralandığı, durumlarının izlendiği tek ekran. Teknik doğrulama (R, SDK'dan): `context.paseo.workspaces.create` + `agents.create` server tarafında mevcut; `toolPolicy` create-config'de var → yetki profili create anında zorlanabilir.

## Karar
1. **Emir şeması (ajan satırı, 5 alan):**
   1) rol + provider/model + mod (K-0015/K-0018)
   2) Sınır — ilk dolan durdurur: bitis saati | süre | kapsam (sprint 1-9) | tokenTavani (v0.10.3 telemetrisi toplar) | turTavani
   3) Yetki profili: salt-okur | raporcu (raporlar/) | planlayici (plans/) | yaratici-worktree (izole kopya; ana dal yasak; birleştirme reviewer kapısından) | yaratici-ana (tek-yazıcı kuralı)
   4) İletişim: kapali (VARSAYILAN) | yalniz-manager (hub) | esler-arasi (mesh — körükleme riski notuyla)
   5) Kapanış kapısı: rapor yolu + kanıt standardı (dosya:hash) + onay (kullanıcı/manager)
2. **Sıralı görev zinciri (kullanıcı eki):** emir listesi sıralı yazılabilir (task1 → task2). Şema alanı: `once: [<emirId>]` — bağımlılıklar ancak öncekinin kapanış kapısı geçince başlar; önceki red/başarısız olursa zincir **bloke** olur (otomatik başlama YOK, kullanıcı kararı).
3. **Durum modeli (kullanıcı eki):** taslak | onay-bekliyor | aktif | pasif | bitti | reddedildi. Kullanıcı onayı olmadan hiçbir emir aktife geçemez. Pasif = ajan kapanmaz, yeni tur emri gönderilmez.
4. **İki akış TEK şema:** manager-topoloji (doğal dil → manager LLM JSON üretir → şema kapısı → kullanıcıya önizleme → onay → kuyruk) VE manuel satır girişi — ikisi de aynı JSON'a düşer; **manager şemasız emir ÇALIŞTIRAMAZ** (şema kapısı create'ten önce).
5. **Zorlama haritası:** modeId (ask/plan) + toolPolicy + permission dar-listesi (v0.10 rol spec'i genişler: planlayici + yaratici-worktree profilleri). Takip hibrit: varsayılan script takipçi (schedule+bekçi); LLM takipçi yalnız anomali hakemi (maliyet freni).
6. **Sol panel (K-0019 ile ortak):** üstte minimal Lighthouse/SEO/CWV şeridi + genel sağlık rozetleri (teknik borç · mimari drift · fake-green · doc↔kod↔plan · plugin uyumu) · altında **detaylı görev listesi: bitenler / kalanlar gruplu**, satırda rol+mod rozeti, kalan süre/token/sprint, son aktivite, stall sinyali (pitbull beslemesi).
7. **Kuyruk:** `.verimlilik/emirler.json` — append-only, `schemaSurum: 1`, her emir satırı { id, zincir, once, durum, 5 alan, ts }. Panodan yazma yalnız POST /api/emir dar-listesi üzerinden (K-0019 güvenlik modeli).

## Reddedilen alternatifler
- Serbest metin emir: şema zorlaması olmadan manager üretimi denetlenemez — reddedildi.
- Mesh iletişim varsayılanı: körükleme (ajan-ajan sonsuz diyalog) riski — kapalı varsayılan.
- LLM takipçi varsayılan: sürekli LLM maliyeti — script takipçi yeterli, LLM yalnız hakem.
- Otomatik zincir devamı (başarısızda atla): sessiz kalite düşüşü — bloke + kullanıcı kararı seçildi.

## Sonuç / riskler
- Tek şema = tek doğrulama noktası; manager da manuel de aynı kapıdan geçer.
- Risk: tokenTavani "durdur" eylemi plugin'den henüz doğrulanmadı (cancel yolu) → degrade: dürtme + kullanıcı bildirimi.
- Açık sorular: manager LLM hangi provider/modda koşar (öneri: CERRAH — tek-atım JSON üretimi) · yaratici-worktree birleştirme kapısı ne kadar otomatik (öneri: reviewer onayı elle, otomasyon ileride).
- Uygulama v0.12+ konusu, K-0019 ile birlikte ayrı onay ister.
