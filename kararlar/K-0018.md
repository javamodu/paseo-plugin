# K-0018 — Provider-Modlar (ATÖLYE / MATBAA / CERRAH / SERBEST) (TASLAK 2026-10-12 — kullanıcı onayı bekleniyor)

## Bağlam
Provider'ların faturalama modeli birbirinden çok farklı (süre-bazlı limitsiz, istek-bazlı günlük kota, token-bazlı PAYG) ama ajan disiplini hepsinde aynı çalışıyor: her modele aynı thinking düzeyi, aynı paralellik, aynı doğrulama sıklığı. Bu, kimi-K3 gibi süre-bazlı limitsiz modellerde kapasite israfı; GLM/deepseek gibi PAYG modellerde gereksiz token yakımı demek. Reviewer oturumuyla olgunlaştırılan plan: provider'ın fatura modeline göre dört isimli çalışma modu.

## Karar (taslak)
1. Dört isimli mod:
   - **ATÖLYE** (süre-bazlı limitsiz, ör. kimi-K3): ultra thinking, 6 paralel, cömert bağlam + Context Rot freni, çift-ajan doğrulama.
   - **MATBAA** (istek-bazlı, ör. 1000 istek/gün): high thinking (istek içinde bedava), 1-2 paralel, tek-atım büyük paket, tur sonunda toplu doğrulama.
   - **CERRAH** (token-bazlı PAYG, ör. GLM/deepseek): low/medium thinking, 1 paralel, CODEMAP→tek dosya diyeti, hedefli doğrulama.
   - **SERBEST** (varsayılan): mevcut disiplin.
2. Saklama: `provider-modlar.json` gömülü varsayılanlar + `ayar.json` repo override (v0.6 deseni). Aktif mod state'i DISKE yazılır — bellek-içi state reload'da sıfırlanır (DERSLER: zaman bazlı korumalar PLUGIN_BASLANGIC'a demirlenir).
3. Uygulama noktası: `agent.create` before-hook → provider+model eşleşirse `thinkingOptionId` + systemPrompt mod eki + telemetri tur kaydına `mod` alanı (v0.10.3 altyapısı hazır).
4. Değiştirme kanalları (öncelik sırası): `/mod` slash komutu (sıfır UI riski, önce) → composer pill (açılır menü desteği doğrulanacak; yoksa cycle/panel fallback) → workspace panel. Syntax: `/mod atolye codex/kimi-K3`.
5. Ölçüm: pano üç ayrı satır — iş/saat (ATÖLYE) · iş/istek (MATBAA) · iş/1k token (CERRAH).
6. Sınır: tur ortası mod değişimi YOK (EK-1: cache kırar).

## Açık sorular (kullanıcıya)
- Mod kapsamı: provider+model varsayılanı + workspace override yeterli mi, yoksa ajan-bazlı override da gerekir mi?
- MATBAA kota takibi (kalan istek/gün) kullanıcıya nasıl görünür olacak — pano satırı yeterli mi?

## Sınır
Sözleşme ailesine (ANAYASA/REHBER/PLAN) dokunulmaz. Plugin kodu bu kararın kapsamı dışında — v0.11 konusu, ayrı onay ister. Kuyruk işi olarak ele alınır; uçuştaki işler (W42 telemetri, proje-panosu, takip-sozlesme) öncelikli kalır.
